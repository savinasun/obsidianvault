## RL Framework
---
RL is the framework where an **agent** learns to maximize cumulative **reward** through interaction with an **environment**, without explicit supervision on which actions to take.

+ **Agent**: learner, decision-maker
+ **Environment**: challenges to be solved
+ **State**: environment snapshot at a given time
+ **Action**: agent's choice in response to state
+ **Reward**: feedback for agent action

## Markov Decision Process (MDP)
---
An MDP is a tuple $(S, A, P, R, \gamma)$:

| Symbol | Meaning |
|--------|---------|
| $S$ | State space |
| $A$ | Action space |
| $P(s' \mid s, a)$ | Transition probability |
| $R(s, a)$ | Expected immediate reward |
| $\gamma \in [0,1)$ | Discount factor |

The **Markov property**: the future depends only on the current state, not the history.
$$
P(s_{t+1} \mid s_t, a_t, s_{t-1}, a_{t-1}, \ldots) = P(s_{t+1} \mid s_t, a_t)
$$

A **policy** $\pi(a \mid s)$ is a probability distribution over actions given a state.

## Value Functions
---
**State-value function** $V^\pi(s)$: expected discounted return starting from state $s$ under policy $\pi$:
$$
V^\pi(s) = \mathbb{E}_\pi\left[\sum_{t=0}^\infty \gamma^t R(s_t, a_t) \;\Big|\; s_0 = s\right]
$$

**Action-value function** $Q^\pi(s,a)$: expected return starting from $(s,a)$ then following $\pi$:
$$
Q^\pi(s, a) = \mathbb{E}_\pi\left[\sum_{t=0}^\infty \gamma^t R(s_t, a_t) \;\Big|\; s_0 = s,\, a_0 = a\right]
$$

Relationship: $V^\pi(s) = \sum_a \pi(a \mid s)\, Q^\pi(s,a)$

### Bellman Equations
The Bellman consistency equations decompose value recursively:
$$
V^\pi(s) = \sum_a \pi(a\mid s) \sum_{s'} P(s'\mid s,a)\left[R(s,a) + \gamma V^\pi(s')\right]
$$
$$
Q^\pi(s,a) = \sum_{s'} P(s'\mid s,a)\left[R(s,a) + \gamma \sum_{a'} \pi(a'\mid s')\, Q^\pi(s',a')\right]
$$

**Bellman optimality equations** (for the optimal policy $\pi^*$):
$$
V^*(s) = \max_a \sum_{s'} P(s'\mid s,a)\left[R(s,a) + \gamma V^*(s')\right]
$$
$$
Q^*(s,a) = \sum_{s'} P(s'\mid s,a)\left[R(s,a) + \gamma \max_{a'} Q^*(s',a')\right]
$$
The optimal policy is then $\pi^*(s) = \arg\max_a Q^*(s,a)$.

## Exploration vs. Exploitation
---
- **Exploration**: try new actions to discover higher rewards
- **Exploitation**: use current best-known action

The **$\epsilon$-greedy** strategy selects a random action with probability $\epsilon$, otherwise the greedy action. $\epsilon$ is typically decayed over training.

## Model-Free vs. Model-Based
---
|| Model-Free | Model-Based |
|---|---|---|
| **Learns** | Policy or $Q$ directly from interactions | A world model $P(s'\mid s,a)$, $R(s,a)$ |
| **Sample efficiency** | Lower | Higher |
| **Compute** | Lower planning cost | Higher planning cost |
| **Examples** | Q-learning, PPO, SAC | Dreamer, MuZero, Dyna |

See [[World Models]] for model-based RL in depth.

## On-Policy vs. Off-Policy
---
**Target Policy:** The policy the agent is trying to evaluate, improve, and optimize. 

**Behavior Policy:** The policy the agent uses to actually interact with the environment and collect data.

**On-Policy:** The **behavior policy and target policy are identical**. The agent learns exclusively from its own current actions and mistakes. If it decides to explore a random move, it evaluates the outcome based on that specific random path (e.g., SARSA, PPO).

**Off-Policy:** The **behavior policy and target policy are different**. The agent can learn from data generated by *any* policy, including stored replays (e.g., Q-learning, DQN, SAC). Enables experience replay and higher sample efficiency.

|Feature|On-Policy Learning|Off-Policy Learning|
|---|---|---|
|**Data Efficiency**|**Low**. Data must be thrown away after a policy update because old data no longer reflects the current policy.|**High**. It can reuse historical data, human demonstrations, or past experiences multiple times.|
|**Core Mechanism**|Evaluates the actual actions taken, including accidental slips or exploratory steps.|Evaluates the absolute best possible hypothetical action, ignoring actual exploratory mistakes.|
|**Experience Replay**|**Incompatible**. Cannot use a replay buffer because old memories are considered stale.|**Compatible**. Relies heavily on replay buffers to hoard and retrain on past transitions.|
|**Training Stability**|Generally **more stable** and easier to converge because the data distribution matches the policy.|**Less stable**. Prone to divergence or training complications due to the mismatch in distributions.|
|**Optimal Path**|Tends to find a **safer, conservative path** that accounts for its own exploratory mistakes.|Finds the **absolute optimal path**, assuming perfect execution later on.


## Key Algorithms Overview
---

| Algorithm        | Type                   | Key Idea                                                                                             |
| ---------------- | ---------------------- | ---------------------------------------------------------------------------------------------------- |
| **Q-learning**   | Off-policy, model-free | Tabular $Q$-value update: $Q(s,a) \leftarrow Q(s,a) + \alpha[r + \gamma \max_{a'}Q(s',a') - Q(s,a)]$ |
| **SARSA**        | On-policy, model-free  | Updates $Q$ using the action *actually* taken next                                                   |
| **DQN**          | Off-policy, model-free | Q-learning + neural network + replay buffer                                                          |
| **Actor-Critic** | On-policy              | Separate actor $\pi_\theta$ and critic $V_\phi$ networks                                             |
| **PPO**          | On-policy              | Clipped surrogate objective; see [[PPO]]                                                             |
| **SAC**          | Off-policy             | Maximum entropy RL; entropy bonus encourages exploration                                             |

## Reward Hacking
---
When the agent finds an unintended way to maximize the reward signal that doesn't reflect the true objective. A fundamental challenge when designing reward functions — the agent optimizes what you measure, not what you mean.

Mitigation: reward shaping, human feedback (see [[RLHF]]), constrained RL.

## Imitation Learning
---
When reward design is hard, learn from expert demonstrations instead. Reduces RL to supervised learning in the simplest case. See [[Behavior Cloning]] for the imitation learning setting and its failure modes.

**Tradeoffs**:
- Expressiveness of the state/action representation vs. sample efficiency
- Generalization from demonstrations vs. online exploration
